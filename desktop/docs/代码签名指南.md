# Windows 代码签名指南

> 本文解决一个问题：**怎么让双击 exe 时不再弹「Windows 已保护你的电脑 / 未知发布者」。**
> 结论先说：必须花钱买证书，而且**买了也不会立刻完全消失**。下面把事实讲清楚，你再决定值不值。

---

## 一、先说三个必须知道的事实（2026 年现状）

这三条来自微软官方文档《[Code signing options for Windows app developers](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options)》（2026-08-29 更新），不是我的推测：

### 事实 1：EV 证书不再能立即免除 SmartScreen 警告

> "Extended Validation (EV) certificates previously bypassed SmartScreen entirely on first download... **That behavior was removed in 2024.**"

很多老教程会说「买 EV 就不弹警告了」——**这个说法从 2024 年起已经失效**。现在 EV 和 OV 的 SmartScreen 表现完全一样。

官方原文：
> "Paying the EV premium ($400+/year) solely to avoid SmartScreen warnings is **no longer justified** — you will still see the same warnings as with an OV certificate."

**所以：不要为了消除警告去买贵的 EV。** 买 OV 就够了。

### 事实 2：签名后警告不会立刻消失，需要「攒信誉」

> "New files can show a SmartScreen warning until they accumulate sufficient reputation... signing consecutive releases with a consistent publisher/signing identity lets publisher reputation build over time."

意思是：签名后**头几个版本仍可能弹警告**，但因为发布者身份一致，信誉会随版本累积，后期版本继承信任。

这就是为什么签名的真实价值在于：**从「永远被拦」变成「熬过一段时间后被放行」**。不签名则是永远从零开始。

### 事实 3：微软自家那个 $9.99/月的便宜服务，中国大陆用不了

Azure Artifact Signing（原 Trusted Signing）确实便宜，但有明确地域限制：

> "Organizations: USA, Canada, EU, UK. **Individuals: USA and Canada only.**"

**中国大陆的个人开发者不在支持范围内。** 这条路直接排除，别浪费时间申请。

---

## 二、你的可行路径

### 路径 A：什么都不做（推荐先这样）

如果只是你自己和团队几个人用，**不签名完全没问题**。

SmartScreen 弹窗点「更多信息 → 仍要运行」就过去了，程序功能不受任何影响。README 里已经写了这个说明。

### 路径 B：买 OV 代码签名证书（要对外分发时）

按官方文档，OV 证书 **$150–300/年**。对中国个人开发者实际可行的渠道：

| 渠道 | 说明 |
|---|---|
| **Certum**（波兰 CA） | 对个人开发者相对友好，国内有代理商（如 ssldun）支持支付宝/微信付款、中文客服。个人版年费约 ¥500 档位的说法流传较广，**实际价格请向代理商确认** |
| **SSL.com IV 证书** | Individual Validated，官网标价 $129/年，面向个人开发者 |
| **GlobalSign / DigiCert / Sectigo** | 国内有官方代理（腾讯云、阿里云云市场等），腾讯云 OV 基础版标价 ¥6800/年，明显更贵 |
| **沃通 WoSign** | 国内 CA，有个人代码签名证书产品 |

**必须注意的两个坑：**

1. **私钥必须存在硬件或云 HSM 里**。2023 年 6 月起 CA/Browser Forum 强制要求，不再发纯 `.pfx` 文件。所以你拿到的多半是 USB 令牌或云签名服务，不是一张能随便复制的文件。
2. **证书最长有效期缩短到约 460 天**。自 2026 年 3 月 1 日起生效（Certum 公告为 2026-02-27 起 459 天）。买「3 年期」实际是通过多次重新签发实现，需要定期操作，不是一劳永逸。

⚠️ 上面的价格是搜索到的公开信息，**下单前务必向卖家核实当前价格和是否支持中国大陆个人申请**。

### 路径 C：开源项目免费签名

如果你的项目符合开源条件，[SignPath Foundation](https://signpath.io) 为合格的开源项目提供免费的 OV 级签名。官方文档明确提到这一点。

不过本项目是私有笔记应用的桌面端，估计不符合条件，仅作为信息列出。

### 路径 D：上架 Microsoft Store（彻底解决，但代价大）

官方文档说这是「大多数新应用的推荐路径」：

> "Microsoft re-signs your package automatically, meaning **users never see a SmartScreen warning** and you never need to purchase or renew a certificate."

**免费、全球可用、完全无警告。** 但要求打包成 MSIX 格式，且要过微软审核、应用需符合商店政策。对私有部署的 NAS 配套客户端来说，通常没必要走这条路。

## 三、我已经配好的东西

不管你现在买不买证书，签名流程已经完整接入工程，**拿到证书后不用改代码**。

### 改动清单

| 文件 | 作用 |
|---|---|
| `build/sign.js` | 自定义签名钩子，支持 4 种模式，凭据全部走环境变量 |
| `electron-builder.yml` | 已加 `sign: build/sign.js`，默认 `SIGN_MODE=off` 静默跳过 |

**已验证**：接入签名钩子后重新打包，退出码 0，产物正常，日志无 `[sign]` 输出——说明未配证书时行为与之前完全一致，不会影响你日常打包。

### 支持的四种模式（`SIGN_MODE`）

| 模式 | 用途 |
|---|---|
| `off` | 默认，跳过签名 |
| `pfx` | 传统 `.pfx` 证书文件（2023-06 前签发的老证书仍可用） |
| `azure` | Azure Artifact Signing（中国大陆个人开发者用不了，仅备用） |
| `cmd` | **通用外部命令模式**——适配任意云签名厂商 CLI（SSL.com eSigner、DigiCert KeyLocker、Certum、锐安信等） |

考虑到事实 1 和 2 里的 HSM 强制要求，**你实际最可能用到的是 `cmd` 模式**，因为云签名厂商都提供自己的 CLI 工具。

## 四、拿到证书后怎么用

### 前置条件

签名需要 `signtool.exe`，它随 **Windows SDK** 安装（不是 Windows 系统自带）。
脚本会自动在 `C:\Program Files (x86)\Windows Kits\10\bin\<版本>\x64\` 下查找；
也可用 `SIGNTOOL_PATH` 直接指定完整路径。

### 情况 1：拿到 .pfx 证书文件

```powershell
$env:SIGN_MODE="pfx"
$env:SIGN_PFX_PATH="D:\certs\my-cert.pfx"
$env:SIGN_PFX_PASSWORD="你的证书密码"     # 只设在环境变量里，别写进任何文件
npm run dist
```

### 情况 2：云签名厂商 CLI（最常见）

先按厂商文档装好它的 CLI 并完成登录，然后：

```powershell
$env:SIGN_MODE="cmd"
# {file} 是占位符，脚本会自动替换成待签名文件的实际路径（含空格也安全）
$env:SIGN_COMMAND="C:\tools\vendor-cli.exe sign --file {file} --hash sha256"
npm run dist
```

具体的命令参数格式**必须查你所买厂商的文档**，每家的 CLI 都不一样，我无法预知。

**这个模式的实现细节**（已实测验证）：

- `SIGN_COMMAND` 被当作**命令行模板交给系统 shell 解析**，因此支持管道、重定向等 shell 语法。
- 特意走 shell 而不是 argv 数组，是为了兼容 **`.cmd` 垫片形式的 CLI**：Node.js 自 18.20.2 / 20.12.2 / 21.7.3 起（CVE-2024-27980 修复），直接 spawn `.bat`/`.cmd` 会抛 `EINVAL`。而通过 npm 全局安装的厂商工具，在 Windows 上恰恰就是 `.cmd` 垫片——不走 shell 会直接签失败。
- 待签名文件路径已自动用双引号包裹，并转义内部引号。**含空格和中文的路径都能完整传递**，实测 `C:\My Documents\release dir\笔记 绿色版-1.0.0.exe` 未被切断。
- 该模式下双哈希嵌套的第二轮会被跳过（哈希算法由厂商 CLI 自行决定），这不影响签名有效性。

### 情况 3：Azure Artifact Signing

```powershell
az login
$env:SIGN_MODE="azure"
$env:AZURE_CODE_SIGN_METADATA="D:\certs\metadata.json"
npm run dist
```

### 单独签一个文件（排查问题用）

```powershell
$env:SIGN_MODE="pfx"
# ... 设好凭据
node build/sign.js "release\win-unpacked\笔记.exe"
```

### 验证签名是否生效

```powershell
# 查看签名信息
signtool verify /pa /v "release\笔记-安装程序-1.0.0.exe"

# 或者：右键 exe → 属性 → 数字签名 标签页
```

## 五、安全注意事项

- **凭据只放环境变量，绝不写进代码或配置文件**。`build/sign.js` 里没有任何硬编码凭据，也不应该有。
- **不要把 `.pfx` 或 `metadata.json` 提交到 Git**。建议在 `.gitignore` 里加上 `*.pfx`、`sign-metadata.json`。
- **证书密码别发在聊天里**（包括发给我）。我配置的脚本就是为了让你用环境变量方式填，不需要告诉任何人。
- 签名时的**时间戳**已内置（脚本会依次尝试 DigiCert / Sectigo / SSL.com 三个时间戳服务器）。打了时间戳，证书过期后已签名的程序依然有效。
- 脚本只对 `.exe / .dll / .node / .msi` 签名，自动跳过 `.blockmap`、`.yml` 等附属产物。

---

## 六、我的建议

按你的实际情况（私有部署 NAS 的配套客户端）：

1. **现在**：不签名，直接用。README 已说明 SmartScreen 绕过方式。
2. **如果只在小范围用**：继续不签名。花钱不值。
3. **如果要公开分发给不特定用户**：买 **OV**（不是 EV，理由见事实 1），预算按 $150–300/年 准备，优先考虑 Certum 国内代理或 SSL.com IV。
4. **买之前**：务必确认两件事——① 该 CA 是否接受中国大陆个人申请；② 私钥是 USB 令牌还是云签名，对应的 CLI 怎么用。这两点决定了你能不能顺利签出来。

签名流程我已经配好，你哪天买了证书，设几个环境变量重新 `npm run dist` 就行，不用回来改代码。
