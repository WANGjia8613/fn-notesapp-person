## 1. 前置要求

| 项 | 要求 |
|---|---|
| Docker | 24+ |
| Docker Compose | v2（`docker compose version` 有输出即可） |
| 磁盘 | 1GB 以上空闲（镜像 + 数据；笔记本身很小） |
| 网络 | 能拉取 Docker Hub 镜像 |

国内网络拉不动镜像时，可临时用镜像源（本示例用 DaoCloud，其他可用源自行替换）：

```bash
docker pull docker.m.daocloud.io/library/node:20-alpine
docker tag  docker.m.daocloud.io/library/node:20-alpine node:20-alpine
# 同理替换 postgres:16-alpine、nginx:alpine
```

## 2. 五步部署

```bash
# 1. 拉代码
git clone https://github.com/WANGjia8613/fn-notesapp-person.git
cd fn-notesapp-person

# 2. 生成配置：随机数据库密码 + JWT 密钥写入 .env（权限 600）
./scripts/gen-env.sh
#
#    可选：自定义管理员账号，编辑 .env
#        SEED_ADMIN_EMAIL=you@example.com
#        SEED_ADMIN_PASSWORD=你的强密码
#
#    可选：开启邮件提醒（不填则邮件只打日志，不会真实发送）
#        SMTP_HOST=smtp.qq.com
#        SMTP_PORT=465
#        SMTP_USER=you@qq.com
#        SMTP_PASS=邮箱授权码          # QQ 邮箱是授权码，不是登录密码
#        SMTP_FROM=you@qq.com

# 3. 构建并启动（首次构建前后端镜像，几分钟）
docker compose up -d --build

# 4. 建表 ⚠️ 必须在第 3 步之后立刻执行
docker compose exec -T backend npx prisma migrate deploy

# 5. 创建管理员账号（owner）
docker compose exec -T backend npm run seed
```

第 5 步的注意点：

- `.env` 里**没设** `SEED_ADMIN_PASSWORD` → 脚本随机生成一个强密码，**只在输出里打印一次**，请立即保存
- `seed` 只在账号不存在时创建，**重复执行不会重置已有密码**
- 输出里会打印 `Admin email` / `Admin password` / `Workspace`

打开浏览器：

```
http://<你的机器IP>:8080
```

端口由 `.env` 的 `APP_PORT` 控制，默认 **8080**（飞牛 NAS 的 80/443 通常被系统门户占用，所以没有沿用 80）。

健康检查：

```bash
curl -s http://127.0.0.1:8080/api/health     # 期望 {"status":"ok"}
docker compose ps                            # 四个服务都应为 Up / healthy
```

## 3. 目录与数据位置

| 内容 | 位置 | 说明 |
|---|---|---|
| 项目代码 | 你 clone 的目录 | 只有代码与配置，没有数据 |
| 数据库 | Docker 卷 `<项目名>_pgdata` | 笔记、用户、提醒规则 |
| 附件 | Docker 卷 `<项目名>_uploads` | 上传的文件 |
| 备份产物 | `<项目目录>/backups/` | 由 `scripts/backup.sh` 生成 |

> ⚠️ 附件在**卷**里，宿主机上的 `backend/uploads` 是空的。查看/备份/恢复附件都要经容器，别直接去找那个目录。

数据库卷的真实路径可以用下面的命令查到：

```bash
docker volume inspect "$(basename "$PWD")_pgdata" --format '{{.Mountpoint}}'
```

## 4. 配置项速查

编辑项目根目录的 `.env`（`.env.example` 有完整注释版）。

| 变量 | 默认 | 说明 |
|---|---|---|
| `POSTGRES_USER` / `POSTGRES_DB` | `app` / `notes` | 数据库账号与库名 |
| `POSTGRES_PASSWORD` | — | **必填**，`gen-env.sh` 自动生成随机值 |
| `JWT_SECRET` | — | **必填**，登录 token 签名密钥；为空或弱值会**拒绝启动** |
| `JWT_EXPIRES_IN` | `7d` | 登录 token 有效期 |
| `ICAL_TOKEN_TTL_DAYS` | `90` | 日历订阅链接有效期，过期后在界面上重新获取 |
| `TZ` | `Asia/Shanghai` | 提醒/汇总按本地时间触发，务必设置正确 |
| `TRUST_PROXY` | 空 | **留空 = 只信任私网段**（正确默认值）；`true` = 信任任意来源，**不要用** |
| `CORS_ORIGIN` | 空 | 留空 = 不开放跨域（同源反代场景不需要） |
| `APP_PORT` | `8080` | Nginx 对外端口 |
| `SMTP_*` | 空 | 留空 = LOG 模式（邮件内容打到后端日志） |
| `SEED_ADMIN_EMAIL` | `admin@example.com` | 首次 `seed` 创建的管理员邮箱 |
| `SEED_ADMIN_PASSWORD` | 空 | 留空则随机生成并打印一次 |
| `BACKUP_DIR` / `KEEP_COUNT` | `./backups` / `10` | 备份脚本用 |

改完 `.env` 后重建容器使其生效：

```bash
docker compose up -d
```

## 5. 邀请成员

系统**不开放公开注册**，新成员只能凭邀请加入：

1. 用管理员登录，顶栏进 **「团队与邀请」**（只有 `owner`/`admin` 能看到入口）
2. 填被邀请人邮箱 + 选有效期（1/3/7/30 天）→ 点「生成邀请链接」
3. 复制链接发给对方（局域网 http 访问时也已兼容复制）
4. 对方打开链接 → 设置姓名和密码（至少 8 位）→ 自动加入团队，角色为 `member`
5. 页面下方可查看邀请记录（待使用/已使用/已过期）并随时撤销未使用的邀请

也可以直接调 API（脚本化时用）：

```bash
TOKEN=*** -s -X POST http://127.0.0.1:8080/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"admin@example.com","password":"你的密码"}' \
  | python3 -c 'import json,sys;print(json.load(sys.stdin)["token"])')

curl -s -X POST http://127.0.0.1:8080/api/invitations \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"email":"someone@example.com","expiresInDays":7}'
```

## 6. 外网访问

### 推荐：Cloudflare Tunnel

1. 建 tunnel，把域名指向 `http://localhost:8080`（**不要**指向 80/443，飞牛上那通常是门户跳板）
2. 无需额外配置：后端会根据 `X-Forwarded-Proto` / `Host` 生成绝对链接（邀请链接、日历订阅地址），Nginx 已做透传，所以套在 HTTPS 后面生成的链接自动是 `https://域名/...`

### 或者：自建 Nginx / Caddy 反代

反向代理到 `http://127.0.0.1:8080` 即可。若反代层不是 nginx，请确保透传：

```
Host: $http_host                 # 注意要带端口（nginx 的 $host 会丢端口）
X-Forwarded-Proto: $scheme
X-Forwarded-For: $proxy_add_x_forwarded_for
```

### 注意事项

- ⚠️ **只暴露 Nginx**。`postgres(5432)` 与 `backend(3000)` 已在 compose 里去掉宿主机端口映射，别再加回去
- ⚠️ `TRUST_PROXY` 保持留空。改成 `true` 等于允许伪造 `X-Forwarded-For` 绕过登录限流
- 公网暴露务必使用强密码；登录限流按真实客户端 IP 统计（依赖上面两条配置正确）

## 7. 备份与恢复

### 手动备份

```bash
./scripts/backup.sh
```

产出（自动保留最近 10 份）：

- `backups/db_YYYYMMDD_HHMMSS.sql` — 数据库全量
- `backups/uploads_YYYYMMDD_HHMMSS.tar.gz` — 附件（附件为空时跳过）

### 定时备份

```bash
crontab -e
# 每天 3:00 备份，日志追加到 backups/backup.log
0 3 * * * cd /path/to/fn-notesapp-person && ./scripts/backup.sh >> backups/backup.log 2>&1
```

> 建议把备份目录放到**另一块盘**，避免与运行数据同盘单点故障（`.env` 里用 `BACKUP_DIR` 指定，或直接改 crontab 里的路径）。

### 恢复

```bash
cd /path/to/fn-notesapp-person

# 数据库
docker compose exec -T postgres psql -U app -d notes < backups/db_YYYYMMDD_HHMMSS.sql

# 附件
docker compose exec -T backend tar xzf - -C /app < backups/uploads_YYYYMMDD_HHMMSS.tar.gz
```

`.env`（含数据库密码、JWT 密钥、SMTP 授权码）不包含在备份里，请另行妥善保存 —— 丢了它，恢复出来的数据也用不起来。

## 8. 升级与回滚

### 升级

```bash
cd /path/to/fn-notesapp-person
git pull
docker compose up -d --build
docker compose exec -T backend npx prisma migrate deploy
```

构建期间旧容器仍在服务，重建只需几秒，不会长时间中断。

### 升级到富文本版本（M4）的额外一步

富文本版本给 `Note` 表新增了 4 列、给 `Attachment` 表新增了 `shareToken` 列。
其中 `bodyText`（搜索用的纯文本投影）**带数据回填**，把存量笔记的 `bodyMd` 复制过去 ——
所以升级后搜索行为与升级前完全一致，不会出现"升级完搜不到旧笔记"。

```bash
# 富文本版本部署时，Nginx 配置有变化（新增了 access_log 格式），
# 必须重建 nginx 容器而不是 restart，否则日志格式不生效
docker compose up -d --build nginx
```

回滚友好性：本次迁移全部是 `ADD COLUMN ... DEFAULT`，回退旧代码时不需要动数据库。
富文本笔记的 `bodyMd` 强制为空串，所以旧代码读到的是"暂无内容"而不是执行存储型 XSS。

### 回滚

```bash
git log --oneline -5          # 找到目标版本
git checkout <版本或 tag>
docker compose up -d --build
```

> ⚠️ 数据库迁移是**单向**的。如果新版本带来了结构变更（`backend/prisma/migrations/` 下有新目录），回退代码前需要先用对应的备份还原数据库。升级前建议先跑一次 `./scripts/backup.sh`。

## 9. 常见问题

**Q：启动日志出现「数据表尚未创建」/ `P2021`**

只是启动顺序问题 —— 提醒引擎在容器启动瞬间会先扫描一次，而 `migrate` 是紧接着才执行的。按第 2 步的第 4 条跑一次迁移即可，之后不会再出现。

**Q：忘记管理员密码**

`.env` 里设好 `SEED_ADMIN_PASSWORD`，把该用户删掉再跑一次 `seed`；或者直接改库里的 `passwordHash`（bcrypt）。

**Q：收不到提醒邮件**

1. 没配 `SMTP_*` 时是 LOG 模式，只会把邮件内容打进日志（`docker compose logs -f backend`）
2. 到「提醒设置」页点 **「测试邮件」**，返回里会带 `mode` 与 `messageId`
3. 提醒按 `TZ` 的本地时间触发，检查容器时区是否符合预期

**Q：一篇笔记会发几封邮件**

`remindAt`（提醒时间）与 `dueAt`（到期时间）各生成一条独立提醒，两个都填就会各发一封。接收人是**作者 + 被显式共享的成员**。

**Q：改期之后提醒还会发吗**

会。改期后旧的 pending 提醒会被自动作废并按新时间重建，已发送的保留为历史记录。

**Q：邀请链接打开后域名/端口不对**

检查反代是否透传了 `Host`（要带端口，nginx 需用 `$http_host` 而不是 `$host`）与 `X-Forwarded-Proto`。本项目自带的 `nginx/default.conf` 已处理好这两种情况。

**Q：日历订阅链接过期了**

订阅链接默认 90 天有效（`ICAL_TOKEN_TTL_DAYS`）。到「提醒设置」页重新获取一次，把新地址更新到日历客户端即可。

**Q：附件传不上去 / 找不到**

- 单文件上限 50MB（`backend/src/routes/attachments.ts` 与 nginx 的 `client_max_body_size` 一致）
- 附件存在 Docker 卷里，宿主机上的 `backend/uploads` 是空的

**Q：Markdown 笔记和富文本笔记有什么区别？笔记标题栏的角标是什么意思**

笔记正文有两种格式，**同一篇笔记只能是其中一种，编辑器右上角有角标标明**：

| | Markdown 笔记 | 富文本笔记 |
|---|---|---|
| 编辑方式 | 直接写 Markdown 源码，所见即所得的只有「预览」态 | 全部按钮操作，不需要记语法 |
| 表格 / Mermaid | 支持（预览态渲染） | 不支持 |
| 代码块 | 支持 | 支持 |
| 图片 | 走侧边栏「附件」上传后插入 | 工具栏 🖼 按钮直接插，自动上传 |

- 角标 **Markdown**：存量笔记，升级后完全没变样
- 角标 **富文本**：新建笔记时的默认格式

想在新建时用 Markdown：访问 `/new?format=markdown`。

> 富文本笔记**不能**转成 Markdown 笔记（反过来可以手动复制原文），
> 原因是富文本的任务清单勾选态、标题层级这些结构在 Markdown 语法里没有一一对应。

**Q：想换个端口**

改 `.env` 的 `APP_PORT`，然后 `docker compose up -d`。

**Q：想彻底重置数据重新开始**

```bash
docker compose down -v        # -v 会删除数据库与附件卷，不可恢复
docker compose up -d
docker compose exec -T backend npx prisma migrate deploy
docker compose exec -T backend npm run seed
```

## 10. 安全清单

上线（尤其是暴露到公网）前逐条确认：

- [ ] `JWT_SECRET` 与 `POSTGRES_PASSWORD` 是随机值（`gen-env.sh` 已处理）
- [ ] 只暴露 Nginx 端口，`3000` / `5432` 未映射到宿主机
- [ ] `TRUST_PROXY` 留空，不是 `true`
- [ ] 管理员使用强密码，不用默认账号
- [ ] 反代正确透传 `Host` / `X-Forwarded-Proto`（否则限流会把所有请求算到同一个 IP）
- [ ] `.env` 权限 600，且从未提交进 git（`.gitignore` 已排除）
- [ ] 配好定时备份，且备份不在同一块盘
- [ ] 已核对系统时间/NTP，`TZ` 正确（影响提醒触发时刻）

## 11. 卸载

```bash
cd /path/to/fn-notesapp-person

# 停止并删除容器与网络（保留数据卷）
docker compose down

# 连数据一起删除（数据库 + 附件，不可恢复！）
docker compose down -v

# 需要时再删掉镜像与代码目录
docker image rm fn-notesapp-person-backend fn-notesapp-person-frontend
```

> 删数据前务必先 `./scripts/backup.sh` 并确认备份文件可用。
